## Why Threadbraid

Provider sessions remain separate threads. The product carries verified state
between them at deliberate handoff checkpoints, preserving each thread's
lineage while building a durable project history. A braid is therefore a
system of distinct strands, not a merged conversation.

Threadbraid is:

- pronounceable and unambiguous in speech;
- legible as a Mac application, repository, and terminal command;
- broad enough for the native workspace, Knowledge Core, adapters, and future
  platform without calling the product a CLI;
- specific enough to support an ownable visual metaphor; and
- materially less crowded than names built from `agent`, `hub`, `command
  center`, `continuity`, `relay`, or `handoff` alone.

## Positioning

For developers who use more than one coding agent, **Threadbraid** is the
native agent-continuity workspace that lets them find, resume, hand off, and
supervise work across official agent CLIs while preserving provider lineage,
explicit authority, and local control.

Plain-language category:

> A local coding-agent workspace for macOS.

Strategic category:

> Native agent continuity workspace.

Differentiated promise:

> Switch agents without re-explaining the project or surrendering control.

Primary headline:

> **Switch agents. Keep the work intact.**

Support line:

> A native Mac workspace for verified handoffs between Claude Code, Codex, and
> the tools you add next.

Brand idea:

> **Continuity with custody.**

## Competitive position

The market is already crowded with native/local coding-agent hubs, terminals,
workspaces, dashboards, and command centers. Competitors commonly promise more
agents, more panes, worktrees, shared memory, phone approval, or an all-in-one
surface.

Threadbraid should not lead with “all your agents in one place.” Its ownable
position is **verified continuity**:

- bounded local context rather than indiscriminate transcript copying;
- evidence-backed handoffs rather than implied conversation merging;
- provider switching without starting cold;
- one-writer safety and technically read-only review; and
- explicit permissions, provenance, and local custody.

## Audience

Primary:

- privacy- and performance-conscious Mac developers who actively use Codex and
  Claude Code.

Secondary:

- advanced solo builders coordinating multiple workstreams;
- open-source maintainers using implementation/reviewer patterns; and
- developers with long-running local histories who value provenance and
  explicit permissions.

Do not position the current product as multi-user team SaaS.

## Voice

Threadbraid is:

- **Calm:** measured even when work fails or needs attention.
- **Exact:** separates verified facts, provider claims, and unknown state.
- **Candid:** explains permissions, limits, and side effects before action.
- **Owner-aligned:** keeps the developer as decision-maker.
- **Provider-neutral:** treats every provider as an adapter, not the brand.

Use:

> Claude finished the implementation. Codex is ready to review it with
> read-only access.

Avoid:

> Your autonomous AI swarm crushed the task.

## Terminology

| Prefer | Definition |
|---|---|
| coding agent | Public term for Codex, Claude Code, and future compatible tools |
| provider | Technical term when provider identity materially matters |
| session | Work continuing within one provider |
| resume | Continue the same provider session |
| handoff | Move verified context to another provider |
| verified handoff capsule | The bounded transfer artifact; introduce before shortening to `capsule` |
| project | The owner's canonical local project |
| workspace folder | Explicit filesystem authorization boundary |
| writer | The one session authorized to modify a workstream |
| reviewer | A technically read-only reviewing session |
| local knowledge | Provenance-bearing project context |
| projection | An external representation in GitHub, Linear, Obsidian, or another client |

Avoid `switch conversation`, `merge sessions`, `sync chats`, `unified chat`,
and `autonomous swarm`. They misrepresent the product's lineage or authority
model.

## Visual system

The identity should feel like **quiet infrastructure**.

- **Core metaphor:** distinct strands passing through one controlled,
  verifiable crossing.
- **Mark:** two separate paths alternating around a square checkpoint, with a
  compact negative-space `T`/`B` suggestion; never an infinity loop or merged
  blob.
- **Palette:** near-black ink `#101417`, warm ivory `#F2F0E8`, mineral blue
  `#3F7FA6`, restrained amber `#D6A04A`; muted mint and coral only for product
  status.
- **Typography:** a neutral humanist sans with a precise monospaced secondary
  face; system typography remains acceptable in the native application.
- **Material:** anodized metal, warm paper, fine rules, measured spacing, and
  restrained construction geometry.
- **Motion:** short state transitions only, respecting Reduce Motion.

Do not use provider-owned colors or marks. Do not apply Anthropic's orange,
Poppins, and Lora brand system to this provider-neutral product. Avoid purple
AI gradients, brains, robots, sparkles, cyberpunk terminal green, literal yarn
balls, and decorative knots.

- Claude Code and Codex session manager;
- coding-agent handoff;
- cross-agent context;
- local-first coding-agent history;
- verified agent continuity; and

Suggested homepage title:

Suggested meta description:

> Find, resume, and hand off Claude Code and Codex work from one native Mac
> workspace, with verified local context and explicit permissions.

Do not force `Threadbraid` into copy repeatedly. Pair it with descriptive
category language until the name earns navigational search demand.

## Brand review gates

Before shipping public copy:

1. Distinguish verified current behavior from roadmap behavior.
2. Substantiate privacy, performance, and compatibility claims with current
   evidence.
3. Avoid `only`, `best`, `fastest`, `fully private`, or similar unsupported
   superlatives.
4. Use provider names descriptively and include a non-affiliation statement.
5. Confirm trademark, domain, package, repository, and App Store identities.
6. Review the final mark for similarity to existing software and provider
   identities.

## Decision required

Owner acceptance of **Threadbraid by Openly Useful** turns this recommendation
into a rename plan. Until then, Local Command Center remains the engineering
working title and all public-brand changes are proposals.
